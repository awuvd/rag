# RAG 课程知识问答系统

> 基于 RAG（检索增强生成）的《神经网络与深度学习》教材智能问答系统
>
> 输入一个问题 → 从整本教材中检索相关段落 → 大模型基于这些段落回答，并标注出处

---

## 📖 项目简介

把邱锡鹏《神经网络与深度学习》（444 页）整本教材做成一个**可以提问的知识库**。

与"直接问大模型"的区别：

| | 直接问大模型 | 本项目（RAG） |
|---|---|---|
| 知识来源 | 模型训练时记住的，可能过时/有误 | **教材原文**，可信 |
| 出处 | 给不出 | **标注第几章**，可核对 |
| 幻觉 | 常见 | **资料没有就明确拒答** |
| 私有知识 | 学不到 | 把教材"喂"进去即可 |

---

## ✨ 核心特性

- **🔍 全链路 RAG**：PDF 解析 → 章节切分 → 向量化 → 语义检索 → 大模型生成
- **📚 长文档处理**：444 页教材按**章节结构**切分，保留层级元信息（可溯源）
- **🎯 带出处的回答**：每条回答标注依据来自哪一章，可人工核对
- **🛡️ 防幻觉双保险**：
  1. **代码层拦截**：检索距离超过阈值 → 直接判定"不在教材范围内"，不浪费 API 调用
  2. **提示词约束**：要求模型"只根据资料回答，没有就说没有"
- **⚡ 全离线可用**：向量化模型本地缓存，无需联网（只有生成环节调 API）
- **🧩 模块化设计**：切分 / 向量化 / 检索 / 生成各自独立，可单独测试

## 🖥️ 效果演示

### 场景 1：教材内的问题（正常回答）

```bash
$ py src/week3_D17.py
你的问题是什么：什么是注意力机制

【回答】
注意力机制是一种让模型在处理信息时，根据当前目标动态计算并分配不同权重的方法……
（内容来自教材第 8 章）

【依据】
  · 第8章 注意力机制与外部记忆
```

### 场景 2：检索准确性（不同章节都能命中）

| 提问 | 命中的章节 |
|------|-----------|
| 什么是注意力机制 | 第 8 章 注意力机制与外部记忆 |
| 循环神经网络有什么问题 | 第 6 章 循环神经网络 |

> 实测：top-5 结果**全部来自正确章节**，距离随相关性递增（0.47 → 0.72）

### 场景 3：教材外的问题（拒答，不编造）

```bash
你的问题是什么：红烧肉怎么做
【回答】
这个问题不在教材范围内
```

> 实现方式：检索到的**最近距离仍 > 0.9** → 说明教材里根本没有相关内容 →
> **代码直接拦截**，而不是指望模型"听话"

## 🛠️ 技术栈

| 环节 | 选型 | 说明 |
|------|------|------|
| PDF 解析 | `pypdf` | 提取文字层 |
| 文档切分 | 正则定位章节 + 滑动窗口 | 按书本结构切，非暴力均分 |
| 文本向量化 | `BAAI/bge-base-zh-v1.5` | 中文语义嵌入，输出 **768 维** |
| 向量数据库 | `Chroma` | 本地持久化，余弦距离 |
| 大模型生成 | `DeepSeek API`（OpenAI 兼容）| 中文效果好、成本低 |
| 语言/环境 | Python 3.10 + PyTorch | — |

## 🔄 系统架构

```
                        【离线构建，一次性】
  PDF (444页)
      │  ① pypdf 提取
      ▼
  book.txt (48 万字)
      │  ② 按章节切分 + 滑动窗口（500字/块，重叠50字）
      ▼
  1023 个知识块（带元信息：章节号/标题）
      │  ③ BGE 编码 → 768 维向量
      ▼
  Chroma 向量库 (1023 条)


                        【在线查询，每次提问】
  用户问题
      │  ④ BGE 编码（与建库同一模型）
      ▼
  问题向量 ──⑤ 相似度检索──▶ top-5 知识块
                                 │
                          ⑥ 距离阈值判断
                                 ├─ 距离过大 → 直接拒答
                                 ▼
                          ⑦ 拼提示词（资料 + 问题）
                                 │
                          ⑧ 调大模型生成
                                 ▼
                        回答 + 出处
```

## 🚀 快速开始

### 1. 安装依赖

```bash
pip install pypdf pdfplumber chromadb sentence-transformers openai python-dotenv
```

### 2. 准备 API Key

在项目根目录新建 `.env`：

```
DEEPSEEK_API_KEY=sk-你的key
```

> ⚠️ `.env` 已在 `.gitignore` 中，不会泄露到版本库

### 3. 构建知识库（只需一次）

```bash
# ① 提取 PDF 文本
python src/week1_D3.py

# ② 切分成知识块
python src/week1_D4.py

# ③ 向量化并入库（首次会自动下载嵌入模型，约 400MB）
python src/week2_D12.py
```

### 4. 开始问答

```bash
python src/week3_D17.py
```

## 🔍 关键设计与取舍

### ① 按章节切分，而不是固定长度切

教材有清晰的章/节结构。按结构切分的好处：
- 每块语义完整（不会把一节劈成两半）
- 天然带"来自哪一章"的元信息 → **支持溯源**

遇到的两个真实问题：
- **目录里的"第 N 章"会被误识别** → 用"章号必须依次递增"过滤
- **附录和参考文献会被并入最后一章** → 单独识别附录 A–E 和最后的参考文献

### ② 向量归一化

`normalize_embeddings=True` 让向量长度为 1，此时：
```
点积 = 余弦相似度
```
省掉除法，检索更快；同时让距离度量更稳定。

### ③ 拒绝回答用"代码层"兜底

只靠提示词让模型说"不知道"并不可靠。所以在调用大模型**之前**先判断：

| 情况 | 实测距离 |
|------|---------|
| 教材内问题 | 0.47 ~ 0.50 |
| 教材外问题 | > 1.0 |

取 **0.9** 作为分界（留足余量）。这样：
- 超范围问题**不消耗 API 调用**
- 拒答行为**稳定可控**，不依赖模型发挥

### ④ 检索必须用 `query_embeddings`，不能用 `query_texts`

Chroma 的 `query_texts` 会用**它自带的英文模型**编码查询，与 BGE 的向量空间不匹配——
**不报错，但结果全乱**。必须自己用 BGE 编码后传 `query_embeddings`。
